03: The New Workflow

Three paths. One principle.

Human-in-the-Loop Operating System
The system recommends, documents, and routes. Every recommendation requires human approval before any notification reaches the borrower or a final waiver decision is made.
A
Standard Approval
All GSE and state criteria met. System recommends, analyst confirms, financial capacity verified.
B
Flagged: Extended Review
System identifies a condition requiring extended expert deliberation: ambiguous GSE rule application or contested data. Routes a structured question packet to analyst and Risk.
C
Denied
Hard GSE or state disqualifier confirmed. Analyst signs off, borrower receives clear denial with reason and re-application path, re-evaluation watch activates automatically.

05: Financial Capacity Scorecard

02Both GSEs require financial capacity assessment.
Neither defines how to do it.

We've built a documented, defensible methodology that reduces our compliance exposure, protects against fair lending risk, and produces a structured decision: not a gut call.

A1
Standard Confirmation
All capacity signals present, clean, and unambiguous. Direct recommendation: no scoring required.
Payment history clean across GSE-specific lookback window
No prior waiver violation
Escrow surplus history: CONSISTENT_SURPLUS
No contested data inputs
A2
Compensating Factor Scorecard
One or more signals are thin, borderline, or missing. Scorecard runs on available data and produces a documented conclusion. Risk co-sign required on all A2 approvals.
Triggers when signals present but not definitive: not a second gate
Weighted across five behavioral and financial factors
Pass threshold: 60 / 100 points
prior_waiver_violation = TRUE is a hard disqualifier regardless of score
FactorMaxThresholdsJustification
payment_shock_ratio3535 if ≤10% · 20 if 11–15% · 0 if >15%Most direct answer to the GSE's question. CFPB research: obligations below 10% of income correlate with near-zero delinquency.
escrow_surplus_history2525 CONSISTENT · 10 NEUTRAL · 0 DEFICITDirect behavioral evidence from the loan itself. Observed behavior, not a proxy.
debt_to_income_ratio2020 if ≤36% · 10 if 37–43% · 0 if >43%36% DTI is the established underwriting ceiling for financial flexibility. Less biased than credit score.
income_volatility_12mo1515 CoV ≤0.2 · 8 CoV 0.21–0.35 · 0 >0.35Measures predictability regardless of income source. Protects non-traditional earners from disparate impact.
income_trend55 if GROWING or STABLE · 0 if DECLININGDirectional tiebreaker only.
Maximum100
60
Pass Threshold: Equivalent Risk Substitution
60 points represents the minimum compensating factor score at which default risk on tax and insurance obligations is comparable to an A1 borrower. Anchored to Urban Institute HFPC and FHFA research on alternative credit assessment.
Citation available on request. Weights to be validated against Happy Mortgage loan performance data over time.
Fair lending note: income_type is collected for disparate impact monitoring only: never used in scoring. The scorecard measures what borrowers do, not how they earn. Protects non-traditional earners including freelancers, creators, and contract workers.

Design Principle Description
Investor-aware branching at every step Fannie and Freddie diverge on seasoning, payment lookback, and ineligible loan types. investor_type is evaluated first — correct GSE rules applied automatically at every downstream step.
State rules as a configurable table State-specific LTV thresholds, notice timing, and denial language pre-loaded in STATE_RULES. State law changes update the table, not the workflow. Servicer-specific overlays can be added without redesign.
income_type: collected but never scored Captured for fair lending monitoring and disparate impact auditing only — never used as a decision input. Protects against bias toward traditional employment structures and non-traditional earners.

Supporting Detail
A: Current State Pain Points That Informed This Design
Every design decision in the new workflow traces back to a specific failure in the current process.
Critical Gap

No structured intake

Free-form requests result in incomplete data capture. Every downstream step is slower and more error-prone as a result.

→ Fixed by: structured intake form, required fields enforced at submission
Critical Gap

Manual eligibility = inconsistency at scale

Error rate tied directly to individual analyst quality. A new hire and a 10-year veteran apply different standards.

→ Fixed by: automated hard stop and eligibility engine: same rules applied to every case
Critical Gap

GSE rules live in analysts' heads

Fannie and Freddie diverge on seasoning, payment lookback, and ineligible loan types. Guide updates don't propagate instantly.

→ Fixed by: investor-aware branching in eligibility engine; STATE_RULES table for state-specific overrides
Compliance Risk

No audit trail

Decision reasoning rarely captured in a structured way. Improper approvals indefensible in an investor audit.

→ Fixed by: eligibility_check_log JSON on every case; dual sign-off on A2 and Path B
Compliance Risk

State rules not systematically enforced

Notice timing, denial language, and LTV thresholds vary by state. Compliance depends entirely on analyst awareness.

→ Fixed by: STATE_RULES table; state_notice_deadline calculated field; denial template auto-selected
Systemic Gap

Zero post-waiver monitoring

Tax delinquency and insurance lapse discovered reactively: after investor collateral is already exposed.

→ Fixed by: POST_WAIVER_MONITORING table; Triggers #10–#13; re-evaluation watch (#14)

15a
Slack
Notice Deadline Warning — 5 Days Out
Target
Assigned analyst (assigned_analyst_id)
Timing
Proactive — fires 5 days before state_notice_deadline if request is still open. Advance warning to give analyst time to act before the compliance window closes. State deadline calculated from STATE_RULES.required_response_days at intake.
Purpose
Prevents state notice timing violations before they happen. Gives the analyst runway to make a decision or escalate without being caught at the deadline.
Action Required
Analyst reviews case status and prioritizes for decision. Escalates to Risk if case is unresolved and deadline is at risk.
state_notice_deadline - TODAY() = 5 AND request_status NOT IN (APPROVED, DENIED)
"Notice deadline approaching: [Borrower Name] | Loan #[ID] | Decision required by [state_notice_deadline] per [state] state regulations. 5 days remaining. Review and prioritize."
15b
Slack
Notice Deadline Alert — 2 Days Out
Target
Assigned analyst (assigned_analyst_id)
Timing
Hard alert — fires 2 days before state_notice_deadline if request is still open. Paired with Trigger #15a as a two-stage warning system: advance notice at 5 days, urgent alert at 2 days.
Purpose
Last-resort compliance protection. A missed state notice deadline creates regulatory exposure regardless of the underlying decision. This trigger ensures it never happens silently.
Action Required
Analyst must make a decision or escalate immediately. If case cannot be resolved in time, compliance team should be notified.
state_notice_deadline - TODAY() = 2 AND request_status NOT IN (APPROVED, DENIED)
"URGENT: Notice deadline in 2 days: [Borrower Name] | Loan #[ID] | Decision required by [state_notice_deadline] per [state] state regulations. Decision or escalation required today."
